# Releasing

UniMRI uses [Semantic Versioning](https://semver.org). The version lives in
**one place**: `__version__` in `src/unimri/__init__.py` (hatchling reads it;
`CITATION.cff` is kept in sync by a test).

## Steps

1. Ensure `main` is green (CI + docs).
2. Bump the version:
   - `src/unimri/__init__.py` → `__version__`
   - `CITATION.cff` → `version:` and `date-released:`
   - `CHANGELOG.md` → move items from `## [Unreleased]` into a new
     `## [X.Y.Z] - YYYY-MM-DD` section.
3. `pip install -e ".[dev]" && pytest` — the metadata-consistency test must pass.
4. Commit: `Release X.Y.Z`.
5. Tag and push:
   ```bash
   git tag vX.Y.Z
   git push origin main vX.Y.Z
   ```
6. The **Release** workflow then:
   - verifies the tag matches `unimri.__version__`,
   - builds the sdist + wheel and runs `twine check`,
   - publishes to PyPI via Trusted Publishing (configure the publisher once at
     <https://pypi.org/manage/account/publishing/>: project `unimri`, workflow
     `release.yml`, environment `pypi`),
   - creates a GitHub release with autogenerated notes and the artifacts.

## First release checklist (one-time)

- [ ] Finish the name / PyPI / trademark clearance.
- [ ] Create the PyPI project and configure Trusted Publishing.
- [ ] Enable GitHub Pages for the `gh-pages` branch (the Docs workflow creates it).
- [ ] Add the Zenodo integration for a DOI, then enable the DOI badge in the README.
- [ ] Uncomment the PyPI / docs / DOI badges in `README.md`.
